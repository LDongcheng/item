# 智能体技术路线文档

> 项目：AI赋能商家平台（fsj）| 更新日期：2026-05-01

---

## 一、整体架构

```
用户输入
    ↓
第一层：MiniMax-M2.5（快速响应）── 1秒内极简回复
    ↓
第二层：Coze Workflow HAP API（深度执行）── 调用16个技能操作数据
    ↓
迭代记忆 + 知识库 → 自进化
```

### 1.1 双层响应策略

| 层级 | 模型/API | 首字延迟 | 完整响应 | 作用 |
|------|---------|---------|---------|------|
| **第一层** | 百炼 qwen3-coder-next | **~500ms** | **~800ms** | 流式输出一句话，告诉用户"正在做什么工作" |
| **第二层** | Coze Workflow HAP API | 异步 | 1-3s | 深度思考、数据操作、任务执行 |

**为什么选 qwen3-coder-next**：不深度思考，首字 500ms 到达，完整响应 <1 秒，Token 消耗极少。对比 MiniMax-M2.5 强制 thinking 需 12+ 秒，qwen3-coder-next 作为快速响应完全胜任。

## 二、第一层：快速响应（MiniMax-M2.5）

### 2.1 触发时机

用户发送消息后**立即触发**。

### 2.2 响应格式

仅返回**一句话**，说明正在执行什么操作。

**示例**：

| 用户输入 | 快速回复 |
|----------|----------|
| "帮我创建一个新客户" | "正在为你创建客户记录..." |
| "查询本月拜访数据" | "正在查询本月拜访统计..." |
| "更新这批客户的状态为已签约" | "正在批量更新客户状态..." |

### 2.3 实现方式

前端流式调用，首字 500ms 内到达：

```javascript
// 用户输入后立即开始流式输出
const quickText = await AIService.quickReply(userMessage, function(token, fullText) {
  // 实时更新气泡内容
  updateStreamingBubble(fullText);
});
```

API 端点：`https://coding.dashscope.aliyuncs.com/v1/chat/completions`（OpenAI 兼容协议）

## 三、第二层：深度执行（Coze HAP API）

### 3.1 触发时机

第一层快速响应的**同时**触发，不阻塞。

### 3.2 API 端点

```bash
POST https://api.coze.cn/v1/workflow/stream_run
```

### 3.3 请求参数

```json
{
  "workflow_id": "7634531869195796499",
  "parameters": {
    "appkey": "商家HAP应用appkey",
    "content": "用户原始输入",
    "org": "组织rowid",
    "rowid": "记录rowid（按需）",
    "sign": "签名"
  }
}
```

### 3.4 执行流程

```
Coze Workflow 接收请求
    ↓
智能体解析用户意图
    ↓
匹配 16 个 HAP 技能中的一个或多个
    ↓
执行数据操作（增删改查/建表/统计）
    ↓
读取迭代记忆（历史上下文）
    ↓
读取知识库（行业知识/商家资料）
    ↓
返回执行结果 → 推送到前端
```

### 3.5 自进化机制

每次执行后的结果会写入迭代记忆，下次调用时带上历史上下文：

- **成功操作**：记录操作方式和上下文，下次优先复用
- **失败操作**：记录错误原因和修正方案，避免重复踩坑
- **用户反馈**：用户对结果的满意/不满意会标记到记忆中

## 四、智能体页面设计

### 4.1 顶部导航

智能体聊天页面顶部，在聊天区域上方，显示三个按钮：

```
┌──────────────────────────────────┐
│ [ 任务 ]      [ 技能 ]      [ 设定 ] │
├──────────────────────────────────┤
│                                  │
│         聊天消息区域              │
│                                  │
└──────────────────────────────────┘
```

### 4.2 任务

- **位置**：顶部左侧按钮
- **功能**：查看和管理分配给该智能体的任务队列
- **交互**：点击弹出任务列表面板
  - 显示任务列表（状态：待执行 / 执行中 / 已完成 / 失败）
  - 可暂停/恢复/取消任务
  - 可查看任务详情和执行日志

### 4.3 技能

- **位置**：顶部中间按钮
- **功能**：查看智能体当前具备的技能列表
- **内容**：
  - HAP 16 个技能（建表、增删改查、统计等）
  - 自定义技能（商家自行配置）
  - 技能状态（启用/禁用）

### 4.4 设定

- **位置**：顶部右侧按钮
- **功能**：智能体个性与行为设置
- **核心文件**：**SOUL.md**
  - 每次运行**必读**文档
  - 定义智能体的身份、性格、行为准则
  - **用户可编辑**：商家可以在设置页面自定义 SOUL.md 内容

### 4.5 全局设置（AGENTS.md）

- 也是每次运行**必读**文档
- 与 SOUL.md 的区别：
  - `SOUL.md`：单个智能体的个性设置，用户可修改
  - `AGENTS.md`：**全局设置**，所有智能体共享，系统级配置
- 内容占位：AGENTS.md 的获取方式和内容待定，后面由林东城配置
- **代码预留**：智能体初始化时先加载 AGENTS.md，再加载 SOUL.md

## 六、关键技术决策

### 6.1 为什么用 qwen3-coder-next 做快速响应

| 指标 | qwen3-coder-next | MiniMax-M2.5 |
|------|------------------|--------------|
| 首字延迟 | **506ms** | 31s（等待 thinking 完成） |
| 完整响应 | **500-800ms** | 12.4s |
| 深度思考 | ❌ 不思考 | ✅ 强制思考 |
| Token 消耗 | ~67 total | ~175+ |

不深度思考反而适合快速响应场景——用户只需要一句"正在处理中"，不需要模型展开推理。

### 6.2 为什么 Coze API 用 stream_run

- 流式返回，用户可以实时看到执行进度
- 适合长任务（多步数据操作）
- 失败时可以中途反馈

### 6.3 记忆加载顺序

```
1. 加载 AGENTS.md（全局设置）
2. 加载 SOUL.md（个性设置）
3. 加载迭代记忆（历史对话/操作记录）
4. 加载知识库（行业知识/商家资料）
5. 执行用户指令
```
