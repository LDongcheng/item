# 天道地场架构

> 核心设计：天干为道（本源属性），地支为场（场景场所）

---

## 设计理念

### 天干 vs 地支的选择

| 方案 | 优势 | 劣势 |
|------|------|------|
| **天干** | 元数据、本质属性、稳定、先天 | 只有10个，和12维不匹配 |
| **地支** | 正好12个，数量对应 | 杂气藏干、后天形成、不够"元" |

### 最终方案：双层系统

```
地支（维度/场景） = 12维 = 存储位置
天干（属性标签） = 数据本质 = 内容属性
```

---

## 为什么这样设计

### 地支 = 场景（后天形成的实际维度）

- 地支代表"实际场景"，正好对应12维
- 维度就是场景，数据存在哪个维度取决于它的用途/场景
- 12个地支 = 12个维度 = 12个存储位置

### 天干 = 属性（先天形成的本质）

- 描述数据的本质属性
- 让AI知道数据该怎么思考、能不能发散
- 阳干（甲丙戊庚壬）= 稳定、成熟、集体数据
- 阴干（乙丁己辛癸）= 可发散、不确定、个人数据

### 藏干 = 维度特性

- 藏干表示该维度"可能涉及哪些属性"
- AI识别场景后，知道该维度可能涉及哪些数据类型

## 数据结构示例

每条数据有两个标识：

```javascript
{
  "dimension": "寅",     // 地支：存放在哪个维度（场景）
  "attribute": "甲",     // 天干：数据的本质属性
  "content": "...",      // 具体内容
  "created_by": "agent_001"
}
```

### 示例1：技能数据

```javascript
{
  "dimension": "寅",     // 1维技能场景
  "attribute": "甲",     // 甲木：阳，技术成果，成熟稳定
  "content": "移动控制Skill",
  "level": 2
}
```

**解读**：
- 存放在1维（寅）技能维度
- 属性是甲木，表示这是成熟的技术成果，不应随意修改

### 示例2：想法数据

```javascript
{
  "dimension": "卯",     // 2维想法场景
  "attribute": "乙",     // 乙木：阴，创意，可发散
  "content": "尝试用AI自动生成组件",
  "status": "待验证"
}
```

**解读**：
- 存放在2维（卯）想法维度
- 属性是乙木，表示这是创意想法，可以发散、讨论、修改

## 天干属性详解

### 阳干（稳定、集体、成熟）

| 天干 | 五行 | 含义 | 数据特点 |
|------|------|------|----------|
| 甲 | 木 | 技术成果 | 成熟成形的技术，不应随意改动 |
| 丙 | 火 | 企业推广 | 集体的推广策略，相对稳定 |
| 戊 | 土 | 资源支出 | 企业资源，具象具体 |
| 庚 | 金 | 规则制度 | 明确的规范，非流动 |
| 壬 | 水 | 市场规划 | 集体的市场数据，稳定 |

### 阴干（可变、个人、不确定）

| 天干 | 五行 | 含义 | 数据特点 |
|------|------|------|----------|
| 乙 | 木 | 想法创意 | 未验证的想法，可以发散讨论 |
| 丁 | 火 | 交流 | 个人交流数据，多样化 |
| 己 | 土 | 心得收入 | 个人经验，各有不同 |
| 辛 | 金 | 价值观 | 个人价值理念，可个性化 |
| 癸 | 水 | 决策计划 | 个人决策，可能变化 |

## AI思考流程

```
1. 识别场景 → 定位地支维度
2. 查看藏干 → 知道该维度涉及哪些属性
3. 读取数据 → 查看天干属性标签
4. 决策处理 →
   - 阳干数据：沿用，不随意修改
   - 阴干数据：可发散、可创新
```

### 示例流程

**问题**："如何改进移动控制功能？"

```
1. 识别场景 → 技能改进 → 定位寅（1维技能）
2. 寅藏甲丙戊 → 涉及技术、推广、资源
3. 查找1维数据 → 找到"移动控制Skill"
4. 查看属性 → 甲木（阳干）
5. 决策 → 这是成熟技术，改进需谨慎，先在2维（卯）想法中验证新方案
```

## 查询策略

### 默认查询（阳干优先）

```javascript
// 父级查询子级时，默认只返回阳干数据
function queryDimension(dimension, queryType = 'default') {
  if (queryType === 'default') {
    // 只返回阳干属性的数据（甲丙戊庚壬）
    return data.filter(d => YANG_TIANGAN.includes(d.attribute));
  }
  // 显式查询阴干数据
  return data;
}
```

### 场景定向查询

```javascript
// 先定场景（地支），再按属性（天干）筛选
function queryByScene(scene, attributeFilter = null) {
  // 1. 定位地支维度
  const dimensionData = getDimension(scene);

  // 2. 按天干属性筛选
  if (attributeFilter) {
    return dimensionData.filter(d => d.attribute === attributeFilter);
  }

  return dimensionData;
}
```

## 总结

| 角色 | 内容 | 数量 | 作用 |
|------|------|------|------|
| **天干（道）** | 本源属性 | 10个 | 决定数据的"根性" |
| **地支（场）** | 场景场所 | 12个 | 决定数据的"所在" |
| **藏干** | 场景特性 | - | 表示场景涉及哪些属性 |

**一句话**：
> 天干为道（定根性），地支为场（定所在），藏干告诉AI"此场有何道"
