四大核心概念

用外卖的比喻，一秒就懂

Dockerfile

= 菜谱

一份详细的说明书，告诉 Docker 怎么"做菜"：用什么基础食材、加什么调料、怎么烹饪。

# 示例：一份做 Web 应用的菜谱
FROM node:18 # 用什么锅
WORKDIR /app # 在哪做
COPY . . # 放入食材
RUN npm install # 准备调料
CMD ["npm", "start"] # 开始上菜

镜像 Image

= 做好的预制菜

按照菜谱做好的成品，可以无限复制。你不用自己从头做，直接拿别人的镜像用就行。

热门镜像就像网红菜品：

nginx node python redis postgres

运行 Docker 的环境，负责"做菜"

Docker 镜像采用分层存储，就像千层蛋糕：

Layer 4: 应用代码
COPY . /app
Layer 3: 依赖包
npm install
Layer 2: 运行环境
Node.js 18
Layer 1: 基础系统
Ubuntu / Alpine

分层的好处

  • ✓ 复用：公共层可以共享，节省空间
  • ✓ 快速：只下载变化的层，加速构建
  • ✓ 回滚：出问题可以快速恢复到之前版本

常用命令速查

记住这几个就够了

最常用
docker run -d nginx

后台运行一个 nginx 容器

docker ps

查看正在运行的容器

docker stop [容器ID]

停止一个容器

docker images

查看本地所有镜像

docker pull [镜像名]

从仓库下载镜像

docker logs [容器ID]

查看容器日志

docker exec -it [ID] bash

进入容器内部操作

docker build -t name .

根据 Dockerfile 构建镜像

docker-compose up

一键启动多个容器
