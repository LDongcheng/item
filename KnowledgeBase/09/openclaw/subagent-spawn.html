Subagent Orchestrator

subagent-spawn.ts

OpenClaw 的「子Agent孵化器」—— 负责创建、管理和监控子Agent的完整生命周期

用生活场景理解它

🏢

像公司部门架构

主Agent是部门经理，可以派遣子Agent（员工）去完成任务。经理不能无限派遣——有层级深度限制、同时活跃人数限制

🎭

像任务委托系统

两种模式：「一次性任务」完成后消失 vs 「长期合作」保持会话持续沟通。还可以附带文件（附件）给子Agent

🔐

像安全代理系统

沙盒隔离确保权限安全——沙盒中的父Agent不能派遣非沙盒子Agent，防止权限逃逸

生成流程全景

嵌套深度控制

当前深度层级

深度限制规则

maxSpawnDepth = 3

默认最大嵌套深度，防止无限递归

maxChildrenPerAgent = 5

同一父Agent同时活跃的子Agent数量上限

childDepth = callerDepth + 1

子Agent深度 = 父Agent深度 + 1

两种生成模式

R

run 模式

一次性任务执行

  • → 任务完成后会话自动清理
  • → 结果通过事件推送给父Agent
  • → 父Agent不应轮询，等待完成消息
  • → 适合：独立、可并行的子任务
S

session 模式

持久会话模式

  • → 需要 thread=true 绑定消息线程
  • → 会话在任务后保持活跃
  • → 可以继续接收后续消息
  • → 适合：需要持续对话的协作任务

核心概念词汇表

SpawnSubagentParams

生成子Agent的参数结构：task、agentId、mode、thread等

SpawnSubagentResult

返回结果：status、childSessionKey、runId、note

childSessionKey

子Agent的会话键，格式：agent:{id}:subagent:{uuid}

spawnDepth

当前嵌套深度，每派遣一层+1

threadBinding

线程绑定，将子Agent关联到消息线程

attachments

附件系统，向子Agent传递文件数据
