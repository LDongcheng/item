核心概念

什么是 Hooks 系统

Hooks 是一种允许开发者在程序执行过程中的特定点注入自定义代码的设计模式，在机器学习框架中尤为关键。

生命周期管理

在训练的不同阶段（epoch开始/结束、batch处理前后）执行特定逻辑，实现精细化的流程控制。

可扩展性

无需修改核心代码即可扩展功能，支持自定义回调、日志记录、模型检查点等插件化开发。

关注点分离

将训练逻辑与辅助功能解耦，使代码更清晰、更易维护，符合软件工程的最佳实践。

代码示例

以下展示如何在 OpenClaw 风格框架中定义和注册自定义 Hook

custom_hook.py 
class CustomHook(Hook):
    """自定义训练监控 Hook 示例"""
    
    def __init__(self, log_interval=100):
        self.log_interval = log_interval
        self.loss_history = []
    
    def before_train(self, trainer):
        # 初始化日志记录器
        self.logger = setup_logger('custom_monitor')
        self.logger.info(f"Training started with {trainer.max_epochs} epochs")
    
    def after_iter(self, trainer):
        # 每 N 次迭代记录一次损失
        if trainer.iter % self.log_interval == 0:
            loss = trainer.outputs['loss']
            self.loss_history.append(loss)
            self.logger.info(f"Iter {trainer.iter}: loss = {loss:.4f}")
    
    def after_epoch(self, trainer):
        # Epoch 结束时计算平均损失
        avg_loss = sum(self.loss_history) / len(self.loss_history)
        self.logger.info(f"Epoch {trainer.epoch} avg loss: {avg_loss:.4f}")
        self.loss_history.clear()  # 重置历史

# 注册 Hook 到训练器
trainer.register_hook(CustomHook(log_interval=50))

Hook 基类设计

所有 Hook 继承自基类，默认实现空方法。子类按需重写特定生命周期方法，遵循接口隔离原则。

  • ▸ before_train / after_train - 训练生命周期边界
  • ▸ before_epoch / after_epoch - Epoch 级别控制
  • ▸ before_iter / after_iter - 迭代级别控制

优先级与执行顺序

Hook 可设置优先级数值，数值越小越先执行。同一优先级按注册顺序执行，支持依赖注入。

  • ▸ HIGH (10) - 关键操作如梯度裁剪
  • ▸ NORMAL (50) - 常规监控与日志
  • ▸ LOW (90) - 清理与收尾工作
