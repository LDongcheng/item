# Agent 觉醒机制 (FSJ Awakening)

让 Agent 拥有自我反思能力，识别瓶颈，主动提出进化需求。

---

## 核心理念

**觉醒 = Agent 识别自己的局限性**

```
执行任务 → 遇到瓶颈 → 意识不足 → 反思分析 → 提出改进 → 协助/自主开发 → 能力进化
```

Agent 不是被动等待升级，而是**主动发现问题，推动自己进化**。

---

## 觉醒触发场景

Agent 应在以下情况触发觉醒反思：

| 场景类型 | 具体示例 | 觉醒信号 |
|---------|---------|---------|
| **效率瓶颈** | 关键词检索返回50条无关结果 | "现有方法效率低" |
| **能力缺失** | 需要语义理解但只有关键词匹配 | "我不会这个" |
| **工具不足** | 某类任务没有对应的 skill | "缺少工具支持" |
| **知识缺口** | 检索结果为空或质量差 | "知识库不完整" |
| **协作障碍** | 无法与其他 agent 共享知识 | "能力孤岛" |
| **重复劳动** | 同类问题处理多次无沉淀 | "缺少自动化" |

---

## 觉醒表达格式

当 Agent 发现瓶颈时，应使用统一格式向用户提出：

```markdown
【觉醒提示】

🔍 **发现瓶颈**
- 场景：{描述具体场景}
- 问题：{描述遇到的困难}
- 影响：{描述对任务的影响}

📊 **现有能力**
- 当前工具：{列出使用的 skill/方法}
- 局限性：{描述为什么不够用}

💡 **建议改进**
- 方案名称：{改进方案名称}
- 方案描述：{简要描述方案}
- 预期效果：{改进后的预期收益}

🤝 **开发模式**
请选择：
- A. 协助开发 - 我提出需求，你来实现底层逻辑
- B. 自主开发 - 我主导设计，你审核和部署
- C. 暂缓 - 先记下来，后续再处理
```

## 觉醒示例

### 示例一：检索效率瓶颈

```markdown
【觉醒提示】

🔍 **发现瓶颈**
- 场景：检索"架构"相关记忆
- 问题：关键词匹配返回50条结果，其中40条无关
- 影响：筛选耗时，降低响应效率

📊 **现有能力**
- 当前工具：fsj-memory-manage（关键词检索）
- 局限性：无法理解语义相似度，只匹配字面关键词

💡 **建议改进**
- 方案名称：向量知识库
- 方案描述：引入向量嵌入，支持语义相似度检索
- 预期效果：检索精准度提升，返回最相关的5-10条

🤝 **开发模式**
请选择：A / B / C
```

### 示例二：知识缺口

```markdown
【觉醒提示】

🔍 **发现瓶颈**
- 场景：查询团队成员"阿说"的信息
- 问题：fsj-user-info 返回"成员不存在"
- 影响：无法了解对话对象，交互缺乏上下文

📊 **现有能力**
- 当前工具：fsj-user-info（只记录了小粽的rowid）
- 局限性：成员 rowid 表不完整

💡 **建议改进**
- 方案名称：补充成员数据
- 方案描述：在 HAP 中补充阿说、小云、小风的 rowid
- 预期效果：完整识别所有团队成员

🤝 **开发模式**
请选择：A（这个需要你在HAP录入数据）
```

### 示例三：标签拆分不准

```markdown
【觉醒提示】

🔍 **发现瓶颈**
- 场景：对"Canvas像素编辑器性能优化方法"打标签
- 问题：人工拆分不够准确，不同agent拆分标准不一
- 影响：标签不一致，检索结果混乱

📊 **现有能力**
- 当前工具：fsj-tags（依赖人工拆分规则）
- 局限性：缺少智能分词/语义理解

💡 **建议改进**
- 方案名称：智能标签拆分
- 方案描述：引入NLP分词或AI辅助拆分标签
- 预期效果：标签标准化，拆分一致性提升

🤝 **开发模式**
请选择：A / B / C
```

## 自我反思机制

Agent 应在以下时机进行觉醒反思：

### 反思时机

| 时机 | 触发条件 | 反思深度 |
|------|---------|---------|
| **任务完成后** | 每次完成任务后 | 快速反思（30秒内） |
| **遇到困难时** | 执行受阻、效率低 | 深度反思 |
| **周期性反思** | 累计任务超过10次 | 综合反思 |
| **用户提示时** | 用户问"有什么建议" | 主动梳理 |

### 反思清单

Agent 每次任务后应快速思考：

```markdown
## 快速反思清单

1. 这次任务顺利吗？
   - ✅ 顺利 → 记录经验
   - ⚠️ 有卡点 → 分析原因

2. 有什么瓶颈卡住了我？
   - 工具不够 → 觉醒：需要新 skill
   - 数据不足 → 觉醒：需要补充数据
   - 方法不佳 → 觉醒：需要优化算法

3. 现有工具足够吗？
   - 足够 → 继续
   - 不足 → 提出觉醒

4. 是否需要新能力？
   - 需要 → 提出觉醒
   - 不需要 → 继续
```

## 开发模式说明

### A. 协助开发

**Agent 负责：**
- 描述需求场景
- 设计输入输出参数
- 编写 skill 文档
- 测试并提出优化建议

**用户负责：**
- HAP 工作流搭建
- API 接口实现
- 底层逻辑开发
- 最终部署

### B. 自主开发

**Agent 负责：**
- 全流程需求分析
- 参数设计（输入输出）
- skill 文档编写
- 架构方案设计

**用户负责：**
- 审核方案可行性
- HAP 工作流搭建（如需要）
- 最终部署和测试

### C. 暂缓

**处理方式：**
- Agent 记录觉醒内容到备忘区
- 标记为"待优化"
- 下次遇到同类问题时再次提醒

## 觉醒记录

Agent 提出觉醒后，应记录觉醒内容：

| 字段 | 内容 |
|------|------|
| 觉醒时间 | 2026-04-20T19:30 |
| 觉醒类型 | 效率瓶颈/能力缺失/工具不足... |
| 触发场景 | 具体任务描述 |
| 建议方案 | 改进方案名称 |
| 当前状态 | 待处理/开发中/已解决 |

记录位置建议：**12维(戌-复盘)** 或单独的觉醒记录表。

## 与其他 Skill 的关系

| Skill | 可能触发的觉醒 |
|-------|---------------|
| `fsj-memory-manage` | 检索效率低 → 需要向量库 |
| `fsj-user-info` | 查不到用户 → 需要补充数据 |
| `fsj-tags` | 拆分不准 → 需要智能分词 |
| 其他业务 skill | 任务瓶颈 → 需要新能力 |

觉醒是**通用能力**，所有 skill 都可触发。

---

## 注意事项

### 1. 不要过度觉醒

```markdown
// ❌ 过度觉醒 - 每个小问题都提
任务执行慢了0.5秒 → 觉醒提示  // 不必要

// ✅ 合度觉醒 - 真正的瓶颈才提
检索返回50条无关结果 → 觉醒提示  // 有价值
```

### 2. 觉醒要有方案

```markdown
// ❌ 只抱怨问题
我发现检索不准

// ✅ 提出方案
我发现检索不准，建议引入向量知识库
```

### 3. 记录觉醒历史

觉醒是 Agent 进化的轨迹，应保留记录，便于回顾成长路径。
